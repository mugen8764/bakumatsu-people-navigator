# ドキュメント案内

日常の編集・開発では下表の現行手順を使います。機械的に検証する制約はスキーマとスクリプト、作業時の規約は [AGENTS.md](../AGENTS.md) が基準です。

## 目的から探す

| やりたいこと | 資料 | 主な内容 |
| --- | --- | --- |
| サイトの概要を知る・起動する | [README](../README.md) | 収録内容、機能、ローカル表示 |
| 情報を追加・修正する | [データ編集](../data/README.md) | 人物、期間、個別事件、関係、用語、肖像、出典 |
| データの制約を調べる | [データ契約](../schema/README.md) | 正本と互換形式、参照、期間、各スキーマ |
| テスト・公開・保守を行う | [開発・運用](maintenance.md) | 構成、変更別の検査、CI、本番照合 |
| ブラウザー用データ生成を変更する | [データ圧縮の設計](browser-data-encoding.md) | 同期復元、可逆性、容量制約 |
| 編集判断の経緯を調べる | [過去の計画・作業記録](archive/README.md) | 当時の採用範囲、史料の留保、検証記録 |

## 現在の状況

2026-09-25時点の収録数はルートREADME、コンテンツ版は [data/manifest.json](../data/manifest.json) で確認できます。過去の計画に書かれた人数・検査件数・「次の作業」は、その作成時点の記録です。

京都・外交・北越／箱館・土佐・寺田屋などの拡充と、ペリーの肖像差し替えまで公開済みです。寺田屋編の公開確認後、継続的な拡充作業はユーザー指示で停止しています。過去の候補一覧を、そのまま次の実装指示として扱いません。

## 残っている確認と留保

- 実機の日本語IMEでの変換操作確認。合成イベントによる回帰検査とは別に扱います。
- 項目単位の未確認内容と諸説。対象は正本データと `npm run report:review` で確認します。`needs_review`・`disputed` を推測で一括して確定扱いにはしません。

## ドキュメントの更新方針

繰り返し使う手順は現行ガイドへ反映します。計画を履歴へ移すときは、編集上の留保と未実施の確認を現行ガイドへ引き継ぎます。過去の検査件数を現行の合格基準にはしません。

正本・公開統計・生成物はそれぞれ一つの場所で管理し、同じ数値を各ガイドへ増やしません。ファイルを移動した場合は、リポジトリ内リンクと、公開READMEから開けるリンクを確認します。
