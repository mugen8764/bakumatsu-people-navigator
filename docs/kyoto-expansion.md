## レビュー案の評価と今回の範囲

人物をまとめて追加するより、一事件で役割・人物・関係・場所を往復できる形を先に完成させる提案を採用した。既存の16時点を保ち、M0～M2の初回対象として池田屋事件、沖田総司、永倉新八を追加する。人数・肖像枚数を目標に未確認の情報を埋める案は採らない。

事件の参加者は全員を現場にいた人物として描かない。今回の役割表示は新選組側と京都守護職の5名に絞り、近藤・沖田・永倉の突入、土方の別隊指揮、容保の制度上の位置を分けた。池田屋にいた尊攘派志士は概要で説明し、今回の人物相関図が事件の全参加者を網羅するとは表現しない。

## データと操作の契約

- `data/events.json` の任意の `incidents` を個別事件の正本とし、互換生成物ではIDをキーにした辞書にする。既存の主要事件16件と区別する。
- `sceneId` は親となる時点。人物名・役割・関与区分・関係・根拠は個別事件に明示し、親の役職を事件当日の情報として自動転記しない。
- 役割カードと相関図は同じ参加者・関係データを使う。現場・別隊指揮・背景を見出しと記号で区別し、色だけに依存しない。スマートフォンでは人物を縦に並べ、関係は一件ずつ横に読める形にする。
- `#event=ikedaya` で事件を直接開く。完全な共有URLは既存パラメーターに `event` を加える。人物・地図・再読込・履歴移動で文脈を保持し、親時点外・対象外の人物・概要への移動で解除する。旧URLに保存済みの事件を混ぜない。
- 人物詳細には事件の役割と戻る操作を先に置き、年単位の人物情報と区別する。新しい人物にも事件への導線を付ける。
- 肖像には出典と転載条件の参照を必須とする。未読込・通信失敗でも人物名と操作を保つ。

## 受け入れ検査

検索から事件、沖田・永倉の人物詳細、事件へ戻る、地図、再読込、ブラウザー履歴を操作する。320pxのライト・ダーク、キーボード、WCAG A/AA、肖像の通信失敗、人物の活動範囲外、旧URLを検査する。データ検査では重複人物・不明参照・活動範囲外・参加者外の関係・出典のないverified・不正な肖像パスを拒否する。公開物には肖像を含め、配信されたコード・データ・画像の内容を照合する。

自動検査と開発時の実操作は、第三者による利用者評価の代わりにはならない。今回その評価は未実施。

公開前検査では `npm run build:site` の公開物検査と、`STATIC_SITE_ROOT=dist` での `npm test`（データ・ドメイン60件、Chromium80件）が成功。人物数・肖像の変更による4枚の画像差分を確認して更新し、地図の6枚は変更していない。出典リンク検査は213件中212件正常、既存の `kwansei_kawaji_letter` の通信失敗1件、明確なリンク切れ0件だった。
