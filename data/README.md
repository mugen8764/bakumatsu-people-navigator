# 歴史データの編集手順

このディレクトリのJSONが正本です。ルートの `data.json`・`data.js` と `SOURCES.md` は生成物なので、直接編集しません。正確なフィールド制約は [データ契約](../schema/README.md)、コマンドと公開手順は [開発・運用](https://github.com/mugen8764/bakumatsu-people-navigator/blob/main/docs/maintenance.md) を参照してください。

## どのファイルを編集するか

| ファイル | 内容 |
| --- | --- |
| `manifest.json` | サイト名、コンテンツ版、更新日 |
| `people.json` | 人物の登録名・読み・別名・生没表示、収録範囲、関連地点・主要事件・用語、任意の肖像と転換点 |
| `person-statuses.json` | 時点別の表示名・役職・所属・立場・位置づけ |
| `factions.json` | 勢力・活動分野の基本情報と時点別状態 |
| `relations.json` | 期間を持つ人物関係と勢力関係 |
| `events.json` | 時点 `scenes`、主要事件 `events`、個別事件 `incidents`、背景解説 `terms` |
| `places.json` | 地点名、概略座標、説明 |
| `sources.json` | 出典URL、該当箇所、本文の内容確認日 |

## 編集の流れ

着手時に一つのテーマへ範囲を絞り、次の項目を作業説明にまとめます。既存IDを確認してから、新しい人物・事件・出典が必要か判断します。

```text
テーマ・理解できるようにすること:
対象: 事件ID、人物ID、時点・期間
既存情報との差: 追加・修正する内容
根拠: 既存の出典ID、追加調査する主張
完成条件: 確認する表示と操作、前後の時点
変更区分: データ／肖像／UI・処理／ドキュメント
```

例えば事件の拡充なら、「事件での役割を確認でき、人物・出典・地図へ移動して元の事件へ戻れる」を完成条件にします。名前や役職を変える場合は、前後の時点で表示すべき内容も先に決めます。人数や関係線の件数を埋めるために未確認情報を追加しません。

1. 何を理解できるようにするかを決め、関連する人物・事件・期間・表示を確認する。
2. 表示する主張を支える資料本文を読み、根拠と未確認の範囲を記録する。
3. 必要な正本JSONを編集し、既存人物・事件・場所への入口をつなぐ。
4. 期間、名前、所属、関与区分、関係線、出典と校正状態を確認する。
5. 生成・検査を行い、追加した内容を画面で確認する。

```sh
npm run build:data
npm run test:data
```

出典カタログを編集した場合は `npm run build:sources` も実行し、生成した `SOURCES.md` を同じ変更に含めます。正本と生成物、掲載件数を変更した場合のREADMEをそろえます。データ検査は参照・期間などの整合性を確認するもので、史実の正しさを自動判定するものではありません。

公開する版番号・更新日を決めたら、`npm run content:prepare -- --version X.Y.Z --date YYYY-MM-DD` で上記の生成と公開用の件数・識別子更新をまとめて行えます。書式と事前確認用の `--dry-run` は [公開準備コマンド](https://github.com/mugen8764/bakumatsu-people-navigator/blob/main/docs/maintenance.md#公開準備コマンド) を参照してください。

編集中はデータ検査と変更箇所の操作確認を使い、仕上げに変更区分に応じた必須検査を行います。資料の該当箇所と留保は正本の出典・校正状態へ反映します。

## 出典と校正状態

新しい歴史的事実には、表示内容を直接支える信頼できる資料を少なくとも1件登録します。優先順位と禁止事項は [AGENTS.md](https://github.com/mugen8764/bakumatsu-people-navigator/blob/main/AGENTS.md) に従います。一般的な人物紹介を、個別の役職・動機・関係の根拠へ自動流用しません。

| `evidence.reviewStatus` | 扱い |
| --- | --- |
| `verified` | 当該項目を支える `sourceIds` が1件以上ある |
| `needs_review` | 項目単位の確認が未完了。推測で埋めない |
| `disputed` | 複数の見解があり、単一の説明に確定しない |

人物の基本情報、時点別状態、関係、個別事件の役割、転換点の根拠はそれぞれ登録します。生年が未確定でも、事件での行動を別資料で確認できる場合があります。すべてを一括して同じ校正状態へ変更しません。

`sources.json` の `locator`（見出し・頁・コマなど）と `contentCheckedAt`（本文確認日）は必ず対で記録します。URLの到達確認だけでは内容確認日を更新しません。展示解説を読んだ場合と、史料原本を読んだ場合も区別します。

追加・変更したURLの到達性は個別に確認します。403・429・通信失敗は本文の不存在を意味しません。本文を確認できた経路と到達性の制約を編集記録へ残し、未読の資料を読んだ扱いにしません。

## 人物と時点別状態

表示名ではなく安定IDを使います。状態の `displayName` は人物の登録名または別名に含め、肩書き・説明の括弧書きを名前へ埋め込みません。改名・通称と役職は別に扱います。

`activeStartSceneId`〜`activeEndSceneId` は、このナビで状態を収録する範囲です。生存期間や生涯すべての活動期間とは限りません。範囲内の人物状態は空白・重複なく用意し、死亡・隠居・帰国・離隊後に古い役職を持ち越さないよう前後の時点を確認します。

`startSceneId` と `endSceneId` は両端を含みます。年ではなく `events.json` の `scenes[].order` で順序を判定するため、同じ年の異なる時点も区別します。

## 勢力・活動分野と関係

`kind: field` は活動分野を表します。医療や支援などの人物を探す分類であり、共通の政治方針を持つ組織への所属とは扱いません。新しい分類を追加する場合は、[id-mappings.json](../schema/v2/id-mappings.json) の互換形式への対応も更新します。

`relations.json` の関係は開始・終了時点を持ち、両端の人物の収録範囲内に置きます。同じ藩・同じ事件に登場するという理由だけでは直接関係を作りません。根拠に合う既存種別がない行為を、師弟・親族・政治協力などへ無理に当てはめません。

## 主要事件と個別事件

`scenes` と `events` は年代の概況、`incidents` はその内側で詳しく読む事件です。既存時点を増やさずに、日付・争点・役割・関係・次の変化を記述できます。

個別事件では `sceneId` を親時点に指定し、人物ごとにその事件での名前と役割を明示します。親時点の役職を事件当日の情報として自動転記しません。親の主要事件とは別の出来事である場合、その人物を主要事件の当事者へも追加する必要はありません。

| `involvement` | 区別するもの |
| --- | --- |
| `onsite` | 現場での関与 |
| `decision` | 意思決定・指揮 |
| `context` | 背景説明上の関係 |

参加者は1〜9名。確認した役割がある人物だけを掲載し、人数を満たすために追加しません。事件内の関係線は参加者同士に限ります。`direction` は `none`（方向なし）、`forward`（aからbへ）、`both`（双方向）です。線の意味と根拠を説明し、対立を直接の戦闘や命令と誤読させないようにします。

個別事件は人物の `eventIds` へ入れず、`incidents[].participants` で人物と結びます。`eventIds` は主要事件を参照します。画面では `#event=teradaya-1866` のように個別事件へ直接移動できます。

## 転換点と短い解説

人物の `turningPoints` は隣接する登録時点を比較し、両時点とも収録範囲内に置きます。前後の行動と文脈を出典付きで編集し、状態文の差分から思想・動機の変化を推測しません。同じ人物の同じ到達時点に複数の比較を置きません。

背景解説は `events.json` の `terms` に登録し、人物・個別事件の `termIds` で参照します。意味と、その場面で知る必要がある背景を短く分けます。`kind: office` の解説は役職名に該当語が含まれる場合にも表示されます。「前藩主」への解説を、現職である根拠にしません。

## 肖像

人物の `portrait` に、画像パス・代替テキスト・画像の出典・利用条件の出典・所蔵表示・原資料・制作時期・本人同定・利用条件・確認日を記録します。必須項目は [portrait.schema.json](../schema/portrait.schema.json) を確認してください。

所蔵機関の目録で人物と画像を照合し、利用条件を確認した画像を `assets/portraits/` に保存します。顔が小さすぎるもの、台紙や色見本が目立つものはカードでの読みやすさも確認します。史料画像に顔の描き足しや生成による復元を加えません。撮影時期が不明ならその旨を残し、選択時点の姿だと断定しません。

現在の公開検査はJPEG・PNG・WebP、1MiB以下の実ファイルを確認します。これを満たしても初回読み込み量の制約は別にあるため、所蔵機関の適切な縮小画像を優先します。差し替え時は画像だけでなく、年代・クレジット・利用条件・旧参照も更新します。

## 画面での確認

検索から対象を開き、人物・個別事件・出典・地図・元の事件への往復を確認します。人物の前後の時点、URL再読込、キーボード操作、320pxのライト・ダーク、画像失敗時の表示も変更に応じて確認してください。

公開手順と必要なテストは [開発・運用](https://github.com/mugen8764/bakumatsu-people-navigator/blob/main/docs/maintenance.md) を参照してください。
