# 幕末人物・勢力ナビ 1853–1869

黒船来航から箱館戦争終結までを、人物・勢力・事件・場所の関係として読む静的ウェブサイトです。
時点ごとの名前・役職・所属・関係の変化を中心に構成しています。

「この時点で誰がどの立場にいて、何が変わろうとしているか」を短時間でつかめる、ビジュアルな歴史ナビゲーションを目指します。

## デザイン上の優先順位

1. 選択時点の事件・主要人物・関係勢力が最初の画面で分かること
2. 人物と勢力の関係変化が図として読めること
3. 320px幅でも検索・年代移動・相関確認が無理なくできること
4. 詳細情報と出典は必要なときに段階的に開けること
5. 史実として誤解を招かない最低限の確認を保つこと

公開サイト: https://bakumatsu-people-navigator.pages.dev/

## 主な機能

- 1853〜1869年の時系列スライダーと前後移動
- 選択時点に応じた人物名・役職・所属の変更
- 前の時点から変わった人物の立場と、開始・終了した関係の表示
- 本名、通称、変名、後年の名前、役職を含む横断検索
- 人物中心の時点別相関図
- 勢力ごとの目的・立場・構成人物・他勢力との関係
- 人物と事件の関連地を重ねた日本地図
- 地点カードから関連人物・事件への直接移動
- 原因・争点・結果をつないだ事件タイムライン
- URLハッシュによる時点・表示・人物・勢力の共有
- 出典・編集方針のページ

## 公開方法

依存関係を固定どおり導入し、公開用の `dist/` を生成してください。

```sh
npm ci
npm run build:site
```

`dist/index.html` がトップページです。`dist/` の内容だけを静的サイトホスティングへ配置してください。アプリケーション自体にバンドルや変換は行わず、開発用のテスト・スクリプト・依存パッケージを公開物から除外します。

本番はGitHub ActionsのCI成功後、検査済みの `public-site` artifact（`dist/` の内容だけ）をWranglerでCloudflare Pagesへ配置します。Cloudflare側のGit連携はリポジトリ参照用に残しますが、自動プロダクションデプロイは無効にします。

公開前に、生成データ、参照ファイル、セキュリティヘッダー、校正状態を確認してください。

```sh
npm run check:release
```

`_headers` はNetlifyとCloudflare Pages向けです。セキュリティヘッダーに加え、HTML・静的データ・スクリプトは更新を再検証し、画像は1日キャッシュする方針を定義しています。GitHub Pagesなど、このファイルを解釈しない配信先では同等のHTTPヘッダーをCDNまたはリバースプロキシ側で設定してください。

### Cloudflare認証情報のローテーション

デプロイ用トークンは少なくとも年1回、または漏えいの疑い・管理者変更があった時点で交換します。

1. Cloudflareで、このアカウントだけを対象に `Pages Write` のみを許可したアカウントAPIトークンを作成する。
2. GitHub Actionsの `CLOUDFLARE_API_TOKEN` と `CLOUDFLARE_ACCOUNT_ID` を新しい値で更新する。値はリポジトリ、Issue、Actionsログへ記載しない。
3. GitHub Actionsで直近の「Deploy to Cloudflare Pages」を再実行し、続く「Production smoke」まで成功することを確認する。
4. 新しいトークンでの公開成功後に、Cloudflareで旧トークンを失効させる。

交換中も旧トークンを先に失効させず、公開経路の停止と復旧不能を避けます。

## データ編集

- `data/*.json`: 人物・勢力・時点・事件・関係・地点の正本データ
- `data.json`: 分割JSONから生成する互換データ
- `data.js`: 分割JSONから生成するブラウザ読み込み用データ
- `src/app.js`: 状態変更と画面描画をつなぐエントリーポイント
- `src/domain.js`: 時点別状態・関係・活動範囲のドメイン処理
- `src/renderers/`: 人物・勢力・相関図・事件などの画面描画
- `src/styles.css`: レイアウトと配色
- `map-data.js`: Natural Earth由来の低解像度地理形状を、このサイト用に投影・変換したSVGパス

人物の状態は `data/person-statuses.json` に追加します。表示期間には `startSceneId` と `endSceneId` を指定し、勢力などの参照には表示名ではなく安定IDを使います。

データ編集後は互換ファイルを再生成してください。

```sh
npm run build:data
```

`data/sources.json` を変更した場合は、公開用の出典一覧も再生成してください。

```sh
npm run build:sources
```

出典本文を確認した場合は、`locator` に該当する見出し・頁・コマを、`contentCheckedAt` に内容確認日を記録します。URLの到達確認だけでは内容確認日を更新しません。

## 注意

- 日付は、定着した旧暦日付と換算後の西暦日付を必要に応じて併記しています。
- 地図は主要地点の位置関係を示すもので、幕末期の藩境・支配範囲・全旅程を再現しません。
- 密約の動機など解釈が分かれる内容は、確認しやすい公的立場・行動・結果を中心に記述しています。
- 正式な研究・引用では、サイト内の出典リンクから原資料・専門文献を確認してください。
- 人物、時点別状態、勢力、関係、事件、地点には項目単位の出典と校正状態を登録しています。直接根拠を確定できない項目は、推測で補わず `needs_review` として公開画面にも明示します。

## 自動テスト

Node.js 24を使用します（`.node-version` と `package.json` で固定）。初回のみ依存パッケージとChromiumを準備してください。

```sh
npm ci
npx playwright install chromium
```

現行データと次期分割データ契約を検証する場合:

```sh
npm run validate:data
```

データ契約の詳細は `schema/README.md` を参照してください。

データ整合性テストだけを実行する場合:

```sh
npm run test:data
```

ブラウザE2Eと表示スナップショットを含む全テストを実行する場合:

```sh
npm test
```

表示スナップショットだけを確認する場合:

```sh
npm run test:e2e:visual
```

意図した表示変更後にWindowsの基準画像を更新する場合:

```sh
npm run test:e2e:visual:update
```

画像比較はOSのフォント描画差を受けるため、Windowsの基準画像だけを公開前の正本とします。CIとWindows以外の環境では画像比較を除外し、同じ画面について、要素の重なり、横スクロール、レイアウトシフト、キーボード・タッチ操作、アクセシビリティをOS非依存の検査で確認します。
ポート4173が別用途で必要な場合は、`PLAYWRIGHT_PORT` に1～65535の未使用ポートを指定してE2Eテストを実行できます。

校正状態の件数を確認する場合:

```sh
npm run report:review
```

出典本文の精密情報と主要事件の網羅率を確認する場合:

```sh
npm run report:sources
```

GitHub Actionsでは、プッシュとプルリクエストごとにactionlintでワークフローを静的検査し、READMEの掲載件数と主要事件の精密出典網羅も含む `dist/` 検査を行います。ChromiumではOS非依存テストをすべて実行し、FirefoxとWebKitでは `@cross-browser` を付けた主要な画面遷移、320px表示、地図連動、キーボード・タッチ操作を確認します。画像スナップショットはWindowsでの公開前検査として実行します。
`main` のCI成功後は、CIが生成した `public-site` artifactをCloudflare Pagesへ配置します。配信成功後、本番の主要5ファイルが同じコミットの内容になったことと、4種のセキュリティヘッダーを自動確認します。
必要に応じてGitHub Actionsの「Production smoke」を手動実行するか、ローカルで `npm run check:production` を実行して同じ検査を再実行できます。
登録済みの公式出典URLは週1回 `npm run check:links` で到達性を確認します。外部サイト側の一時障害を通常のプッシュ検査へ波及させないため、リンク検査は独立した定期ジョブです。

## 公開前チェックリスト

- `npm ci` 後に `npm run check:release` と `npm test` が成功する
- 配信先で `_headers` 相当のHTTPヘッダーが返る
- 存在しないURLからトップページへ戻れる
- ライト、ダーク、320px幅で主要画面を確認する
- `data/manifest.json` の `contentVersion` と `updated` を更新する
- `SOURCES.md` が `data/sources.json` から再生成された最新状態である
- 校正待ち項目とサイト上の注意書きを確認する
- 公開成果物に `LICENSE` が含まれ、サイト内のリンクから参照できる
